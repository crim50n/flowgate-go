# Flowgate 1.1.0

## DNS configuration and diagnostics

- Add read-only `flowgate check DOMAIN` and `flowgate explain DOMAIN` commands. They show configured Blocky DNS handling, Angie routing, and matching explicit or GeoSite rules without modifying files, fetching data, or querying the network.
- Add the explicit `flowgate dns set DOMAIN [--replace]` syntax. The compatible `dns DOMAIN` spelling warns that it changes configuration.
- Track routes created by the DNS command with `managed_by: dns` and remove those routes when changing the primary hostname. Existing user-managed and legacy unmarked services are preserved.
- Reject accidental replacement of an existing proxy or non-Blocky service unless `--replace` is specified. Protect both explicit and inferred primary DNS backends from incompatible `service` changes.
- Make legacy DNS hostname inference deterministic: only a single local Blocky service with a `dns.` or `doh.` prefix may be selected implicitly.

## Routing and configuration safeguards

- Reject Smart DNS proxy or GeoSite suffixes that cover configured reverse-proxy service names. Service domains continue to use authoritative DNS and are never added to Blocky by service configuration.
- Normalize domain case when reading configuration and reject case-insensitive duplicates.
- Detect service hostnames that collide on the existing ACME client/certificate directory name before applying configuration.
- Reject IPv6 and IPv4-mapped IPv6 notation where the gateway requires IPv4, preventing malformed Angie backend addresses.

## Backup and rollback

- CLI changes now back up the previous Flowgate YAML alongside the corresponding previous Angie and Blocky configurations.
- Failed synchronization restores configuration files modified during environment preparation, including the main Angie configuration and removed example stream configuration.
- Report file and runtime rollback failures instead of silently discarding them; restore a previously active Angie process if applying the candidate stopped it.

## Build security

- Update the pinned build and test toolchains to [Go 1.26.10](https://go.dev/doc/devel/release#go1.26.10), including the standard-library fix for [GO-2026-6809](https://pkg.go.dev/vuln/GO-2026-6809). Preserve Alpine 3.22 and the existing Angie/Blocky versions in runtime and test images.

## Upgrade notes

The configuration format remains YAML. `managed_by: dns` is emitted only for DNS routes created or explicitly replaced by the new command. Older unmarked aliases cannot be safely distinguished from user-created services and are retained; remove an unwanted alias explicitly after selecting the correct primary hostname.

Existing conflicting service/proxy rules or ACME names must be resolved before synchronization can succeed. No automatic bank-domain exclusions are added. Use `flowgate check DOMAIN` to inspect configured matches; successful inspection does not establish the client's actual VPN route or application connectivity.

Linux amd64 and arm64 release binaries are static, UPX-compressed, and accompanied by SHA-256 checksums. Publication is gated by unit tests, the race detector, vet, static analysis, vulnerability checks, and the Angie/Blocky runtime integration workflow.
